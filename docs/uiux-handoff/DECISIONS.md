# DECISIONS

| # | 決定 | 原因 |
|---|---|---|
| D1 | 沿用分支 `claude/npm-install-fst7qc` 做 UI 改版，不另開 | 已 ff 到 master HEAD，無分歧；使用者既有慣例 |
| D2 | **不 push master、不部署**；僅推分支與預覽截圖 | 設計包契約＋deploy.yml 僅在 master push 觸發 |
| D3 | 骨骼視覺維持 `KAP_ANAT` 向量（上輪定案），不重啟 PNG 路線 | 設計包亦註明歷史 PNG 路線被替代；0.58MB gzip |
| D4 | 設計包 BASELINE 與 HEAD 一致，不建立新基準，僅加註 HEAD 實測指紋 | inspect 比對 equal=true |
| D5 | 骨骼對位缺陷（偏移／右側黑）列為 UI 改版的一部分，Step 04 處理；不為此改 BONE_PATHS／骨骼 key | 使用者截圖明示要求「骨頭至少要緊貼肌肉」；契約禁止改解剖 path |
| D6 | 動作切換改為「動作庫＋搜尋」為主，保留 `navKeys()`／上一個下一個的相容（不刪函式） | 使用者明示不要一直滑；契約要求保留篩選內導航 |

## 已鎖定設計來源
`02_SPEC/*`、`03_DEMO/screens/*`。如需偏離，先記錄在此欄。

| D7 | 骨骼貼合以「沿軸線擬合骨骼向量」實作，**不向 GPT 要 PNG** | 實測 95–99% 骨骼點落在肌肉圖上；PNG 仍要解決同一個對位問題，且無法同時支援四視圖、逐骨點選、男女與縮放（先前 clean3–6 路線已驗證不足） |
| D8 | 覆蓋層採「方框＝bsvg 方框＋相同 viewBox」，不再假設 inset:0 | 畫布有 padding 後比例會不同；女性／背面 viewBox 起點不同 |
| D9 | 肌肉配色用 CSS 覆寫＋兩個新 class，不改 EX／SC 的資料色 | 設計包角色色為展示層映射；資料指紋必須不變 |
| D10 | 關閉動態光暈／呼吸動畫 | 設計包視覺規格；前幾輪「熱力光暈」是另一份指令，與本設計包衝突，以設計包為準（若使用者要保留，可只在選取肌肉時加描邊） |
| D11 | 骨骼外觀改進走「外部美術＋既有擬合」，不再自己手寫更多 SVG | 手寫向量的寫實度已到上限；PNG 整副對位的路線已證明失敗 |
| D12 | 使用者決定「用免付費方案」：gzip ≤ 1MB 為硬限制，不改發布設定 | 影響骨骼插畫的縮圖與張數取捨 |
| D13 | 舊 Wiki／ExPicker 彈窗不再重新上色，改把 `openWiki`／`openExPicker` 轉到新入口 | 設計包「不再藏在第二套 Wiki 選單」 |
| D14 | 白話層預設；專業層沿用原區塊，不新增三鍵內容主題切換 | 先保證原資料逐項可讀；三鍵留待後續微調 |
| D15 | 插畫骨骼以 manifest 設定對位：用「被取代的向量骨方框」當基準，胸廓另以肋骨方框＋影像內 `ref` 區（第 1 肋上緣～最低肋尖）對齊並橫向壓到方框寬度×1.12；影像內多出的 C7 與下方腰椎不參與對位 | AI 胸廓圖比設計包比例寬（0.93 vs 0.70），直接按全圖對位會讓椎骨錯位 |
| D16 | 背面視圖沿用正面插畫（顱骨、胸廓、骨盆），不另畫 | 需要 GPT 補 skull_posterior／thoracic_ribcage_posterior／pelvis_posterior（選用）；補前先於 QA 註明 |
| D17 | 圖大小：femur 23KB、hand 69KB、胸廓 129KB（長邊 640、WebP q0.72）、顱骨 27KB，合計約 248KB | 免費方案 gzip ≤ 1MB；預留後續步驟空間 |
| D18 | 圖譜用合併後的全部資料：肌肉 194（WIKI_MUSCLES_DB 174＋_2 的 28 筆，其中 8 筆同名覆蓋）、骨骼 143（53＋90） | 舊 Wiki 本來就合併顯示；只列 174／53 會漏掉已有資料。設計包的「174／53」只是第一份資料庫的數量 |
| D19 | 生活別名採明列映射（`KAP_AT_ALIAS`，約 60 筆）＋搜尋原資料的「日常」欄；不含症狀詞 | 設計包 D04：不做疼痛診斷 |
| D20 | 練習：自由練習為主入口；原挑戰（每日、五類題型、計時、XP）整組搬進「進階挑戰」摺疊區，行為不改 | 設計包 D05 |
| D21 | 清除收藏只重設 `kap_ui_v2.favorites`（保留閱讀深度與語言），舊 XP／看過清單／其他產品 key 都不動 | 設計包 D06 |
| D22 | 儲存失敗時收藏暫存在記憶體（關分頁就消失），並顯示「本次暫時無法保存」 | 設計包 M08 |
| D23 | 圖譜卡片不放肌肉縮圖 | 194 張縮圖要逐個算區域裁切，風險高；詳情裡仍有高亮人形 |
| D24 | 介面只用中文，不再有語言切換；英文只當肌肉／骨骼／動作名稱的第二行 | 使用者明確要求（2026-11-01） |
| D25 | 品牌名「KAP」「KINETIC ANATOMY PRO」保留英文；資料庫內文中的英文術語（如 Lisfranc、TFCC）不改 | 品牌與專有名詞；資料指紋須不變 |
| D26 | 插畫一律壓成「網頁看得清楚」：長邊 ≤520px、WebP q0.6 | 使用者要求；免費方案 gzip ≤1MB |
| D27 | 腰椎圖由腰薦圖裁去薦骨；薦骨與尾骨改用骨盆圖 | 兩張圖都含薦骨，避免重疊 |
| D28 | 背面視圖的顱骨、胸廓、骨盆沿用正面圖；肩胛骨用背面圖 | 目前只有這些圖；後視版本可之後補（選用） |
| D29 | 背面視圖的顱骨、胸廓、骨盆改用後視插畫；頸椎與腰椎在背面仍用前面圖（沒有後視版） | 使用者已提供三張後視圖；其餘兩件待補 |
| D30 | gzip 目標壓在 1,000,000 bytes 以下（比 1,048,576 更保守） | 免費方案上限的換算有出入，保留餘裕 |
